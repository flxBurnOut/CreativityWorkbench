# 作品预览与连续制作（2026-09-10）

当前协议 10、29 个核心工具、Skills 0.7.0。保持原有岭南配色、字体和组件，重新组织默认使用流程。

## 用户现在怎样操作

### 网站

新建项目选择“做一个网站”，写一次完整目标，点击“开始制作网站”。不再要求依次填写创意、内容、美术和图片表单。

系统为空项目匹配明确相关的内置文化资料和原创插画，保存统一制作说明并开始同一个网站任务。已有资料与图片保留；没有匹配的主题不强行加入岭南插画。自动发送未连接时，主页面明确显示“复制请求到 WorkBuddy”；完整要求已准备，无需重新编写。

WorkBuddy 实现网站后，将 ZIP 写回原任务 result.zip 或用 website_complete 完成回传。页面自动接收、检查结构并显示初稿。资料包准备成功时任务继续等待真实源码，不再显示整项网站制作完成。

初稿可直接修改，选择“配色与排版／文字内容／图片素材／功能与交互／整个网站”，写一条变化即可。任务包附上本次指定的实际源码，未使用的初稿也能作为修改基础，不必先确认成最终版本。用户满意后只点击一次“使用这个版本”。

结果优先显示，目标与资料折叠在下方；手机页面同样先看结果。默认界面不再暴露底层提示词、任务包采用、各阶段重复输入和服务参数。完整任务说明在详细编辑中为只读，由统一目标整理。

### 小说和视频

小说直接描述故事并查看正文。网页文字服务未配置时，提供明确的 WorkBuddy 写作请求，写回原项目后自动显示；不会伪装成网页模型已可用。

视频直接描述一个连续镜头，保留横竖屏与 2–10 秒时长这些影响交付的选项。描述中明确的时长和画幅自动识别；改参数也同步修改描述。超出单镜头范围时明确提示。现有首帧与其他镜头保持，分镜、声音及细节在详细编辑中按需处理。

生成结果直接在主页面预览，使用时提交同一 Runtime 的版本检查。图片、视频和文字真实生成质量仍由实际服务及人工检查决定。

### 详细编辑和历史

网站使用“查看制作细节与历史版本”，其他作品使用“查看资料、素材与详细编辑”。原五阶段、对象与参考、类型继承、历史版本继续可用。3D 从默认目标卡片移至“更多能力”，仍只支持前期资料。

网站待提交修改及其他作品的修改草稿随项目保存，与已提交制作依据分开；仅输入下一条修改不会把现有初稿判为过期。切换类型时各自草稿保留。原有未打包的手写网站提示词会归档，恢复旧网站后也不会被后来已用过的结果重新占据预览。

## 接口和恢复规则

- website_run：按版本与 requestId 保存统一目标、补齐空项目资料、提交原网站任务。请求重放查回同一个任务。
- website_complete：将原项目 inbox 的 ZIP 交回原任务，可附真实运行与检查记录。相同文件可重放，不覆盖该任务已有的不同结果。
- POST /v1/tasks/:id/website-result：网页直接上传本次源码的入口，保留同源检查、大小与并发限制。
- 普通 website/task_start、website_source_import 和详细编辑流程继续兼容。连续网站任务使用新工具与原任务路径，不调用 task_adopt 采用中间包。
- 任务晚到但目标已改变时，文件保留在原任务；只有当前任务、当前依据匹配才回传到当前初稿。重试保留明确关系，不重复派发未知状态的请求。

## 2026-09-10 实际页面加载失败与缓存隔离

用户重新打开页面时出现优化依赖文件不存在的遮罩。实际 localhost:3001 返回 HTTP 500，原 node_modules/.vite/deps_rsc 的依赖相对路径来自测试副本。测试副本共享了 node_modules 目录，默认预打包缓存也随之共享；测试重建缓存后，原服务仍引用旧模块。

Vite 配置现在将缓存写到当前配置所在检出目录的 .cache/node_modules/.vite/<command>/<mode>，既隔离真实项目与测试副本，也隔离开发和构建。保留 node_modules 路径段，避免当前 Vinext CommonJS 插件再次转换优化后的 ESM；不修改依赖包、不隐藏错误遮罩。缓存目录加入忽略规则。
