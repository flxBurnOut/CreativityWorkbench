# 前端功能入口与操作流程

更新：2026-09-09。本轮解决“看不清有哪些功能、不知道先后顺序”的问题，保留现有 Runtime、MCP、文化规则和项目数据。

## 从首页开始

首页先展示四个可以开始的目标：写一篇故事、做一段视频、做一个网站、准备 3D 文创设计。每个入口说明用途及交付文件，点击后预选对应类型。3D 入口明确只交付前期资料。

新建项目只需选择目标、填写想法；名称选填。创建不会发起生成请求。已有项目从“我的创意”继续。

## 项目里怎样操作

页面顶部显示交付目标和推荐路线。五个阶段为：确定创意、整理内容、设定画风、准备图片、制作与交付。“已有草稿”与“已有成果”依据保存内容显示，不代表质量验收通过。图片候选和网站任务包不会被标为已采用成品。

每步先说明要做什么、会得到什么。共同操作顺序为：填写或生成 → 在“本步生成结果”预览 → 采用满意结果 → 进入下一步。生成提交后定位到结果卡，结果按作品类型和步骤显示，历史仍可查看。

网页文字生成缺少配置时显示设置入口；也可以直接输入已有内容。WorkBuddy 对话创作通过同一项目保存，连接准备仍按 [WorkBuddy 接入说明](WORKBUDDY_CORE.md) 完成。

| 作品 | 推荐路线 |
| --- | --- |
| 故事 | 展开创意方案 → 生成或填写故事内容 → 采用 → “下一步：创作正文” → 生成与采用正文 → 下载 TXT / Markdown。需要配图时选“我也需要配图”。 |
| 视频 | 直接进入制作与交付 → 填写单镜头要求与时长 → 可选首帧 → 生成或导入镜头 → 采用和下载。配音、分镜、合成按需展开。 |
| 网站 | 确认需求与素材 → 准备任务并交给 WorkBuddy → 按结果卡交接请求完成网站制作 → 导入源码 ZIP → 采用并预览。顶部三个步骤可点击定位。 |
| 3D 前期 | 整理设计与美术要求 → 准备概念参考 → 生成并采用资料包 → 下载 ZIP。当前不生成三维模型。 |

图片先从内容提取对象，或手动添加对象。生成结果“放入图片候选”后，在对象卡片点击“选用此图”；已上传图片也按相同方式选用。“修改图片”基于原图提出修改。

资料继承、创作依据和历史版本位于页面下方的“资料继承与历史版本”，不占据主操作区。切换类型仍保留不同类型的草稿。

“功能与操作说明”按作品类型展示路线，并说明网页操作和 WorkBuddy 对话操作的关系。界面示例明确为示例，不再把示例未生成写成真实服务尚未接入。

## 本轮验证

- 隔离 Runtime 8792、前端 3002，使用已有本地模拟适配器；没有调用真实模型账户，没有写入默认真实项目库。
- 浏览器完成从首页选择故事目标、创建、生成创意、采用、生成内容、采用五个小节、跳过配图、生成并采用正文；TXT 已实际保存到下载目录并检查内容。
- 网站完成任务包准备与采用、通过文件选择器导入测试源码 ZIP、采用与静态预览；预览按钮实际响应。测试网站是明确标注的本地夹具，不是 WorkBuddy 生成成果。
- 视频空镜头禁止提交；填写要求后入口可用。图片首帧区默认折叠，不要求先做分镜。本轮未在浏览器调用真实视频服务。
- 验证按类型切换使用说明；在 390 像素手机视口检查首页与项目页面，没有整页横向溢出。
- `npm test`：78 项，76 通过。两项既有 Windows 失败仍保留：目录符号链接权限、文件权限位 0666/0600 断言。
- `npm run lint`、`npm run typecheck`、`npm run build` 通过。构建仍有既有首页静态分类 Unknown 提示。

真实 WorkBuddy 加载、真实供应商质量、队友首次使用体验仍需实际验收；本轮不将本地模拟成功写成外部服务通过。
