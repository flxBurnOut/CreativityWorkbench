# 文化纹理增强：首次配置与验收

当前协议 12，31 个 MCP 工具，Skills 0.9.0。首先完成工作台与本机 Blender 的接入；真实 COS 权限、Token Hub 账户和纹理生成效果由用户首次配置后验证。本文不代表真实云端调用已通过。

## 这一步做什么

在已经生成的模型下点击“增强文化纹理”。工作台沿用这版原需求与已有文化资料，自动整理短纹理描述；无需重新写造型提示词。首版只生成一张 1024×1024 以内的颜色贴图。凉茶题材采用草本插画、细边饰等当代创作表达，广彩相关资料可启发花卉与构图；不将这些 AI 图案称为真实传统工艺复原。

本机 Blender 为原网格整理 UV，导出白模；云端 `hy-3d-texture` 生成颜色图，再由本机把颜色图贴回原网格并打包。检查顶点位置和面连接的几何哈希，原模型继续留在历史里。网页只看一个版本，导出依然是内嵌纹理的 `.blend` 与 GLB。

## 第一次需要做的事

### 1. 创建临时存储桶

进入 [COS 控制台](https://console.cloud.tencent.com/cos)，新建专用存储桶。名称可自行选择，地域选广州，访问权限选“私有读写”。这个桶用于临时模型，无需开启静态网站或版本控制。记录完整桶名（带末尾 APPID 数字）和地域 `ap-guangzhou`。

在工作台「设置 → API 配置 → 文化纹理临时存储」填写桶名和地域。展开首次配置指引，可以复制工作台按实际桶名生成的限定目录权限策略。

### 2. 配置 COS 上传权限

在腾讯云访问管理为专用子用户创建并绑定上面的自定义策略，只允许该桶 `workbench-texture/*` 下的 `PutObject`、`GetObject`、`DeleteObject`。创建该子用户的 API 访问凭据，将 SecretId 与 SecretKey 填入工作台对应输入框。它们用于 COS 签名，与 Token Hub 的 API Key 不同；不要把主账号的全权限密钥发到聊天中。

### 3. 添加过期清理

在该存储桶的生命周期配置中添加规则，只对 `workbench-texture/` 前缀的对象在创建一天后删除。工作台正常结束后会主动尝试清理；生命周期用于断电、长期关闭工作台或清理权限失效时兜底。生命周期按云端规则异步执行，不代表精确到秒的清理承诺。

### 4. 保存并制作一次

文化纹理接口默认 `https://tokenhub.tencentmaas.com/v1`，模型固定 `hy-3d-texture`。当已保存文字接口地址相同且未配置独立纹理密钥时，复用现有 Token Hub 密钥；否则填写独立纹理密钥。显式清除独立密钥会停用该凭据回退，重新填写有效密钥后恢复。

保存配置本身不上传模型、不验证云端权限、不调用付费生成。返回已有模型下方，点击“增强文化纹理”才上传这一个模型并发起请求。官方当前参考价 30 积分/次，1 积分 0.12 元，约 3.6 元/次；COS 另有存储与流量费用，实际以腾讯云账户为准。

## 任务与资源边界

- 普通造型仍由本机 Blender 生成，文字服务/WorkBuddy 只整理受控方案。纹理增强不调用高面数生成、智能拓扑、额外云端 UV 或 PBR 扩展。
- COS 私有对象路径限定为 `workbench-texture/<本机任务ID>/<随机ID>.glb`；仅中转一个最大 32 MiB 的 GLB，读取签名有效一小时。签名链接、Token Hub 密钥和 COS 密钥不写入任务或页面。
- 提交前持久化本机任务与提交阶段；已知腾讯云任务编号只查询，不重复提交。未知提交保留为需核对状态，不自动新建付费任务。重启后有编号的任务可继续查询。
- 默认同一 Runtime 一次一份云端纹理；状态查询去重，临时错误退避至最多一分钟一次。一小时后停止等待并保留原模型，需要用户到腾讯云核对后再重试。
- 取消停止本地处理及本次采用，不等于腾讯云取消计费。已知远端任务仅继续查询完成状态以便清理，不下载/采用晚到结果。
- 颜色图下载只接受受限腾讯云 COS 域名，不携带账户凭据或跟随重定向；最大 8 MiB、1024×1024 PNG/JPEG，转换为 PNG 后内嵌。只使用 `texture_image`，不拿预览缩略图或供应商返回模型冒充结果。
- Blender 仍使用单进程、1 GiB、180 秒预算。贴图整理后检查原网格几何哈希不变，重开 `.blend` 验证纹理内嵌，GLB 经过现有浏览器预算校验。
- 正常完成与明确失败会清理本轮本地中间目录和临时云对象；云端清理失败单独提示。未知提交会保留暂存用于核对；过期/取消任务在后续查询时清理，长期不开工作台仍需要云端生命周期兜底。

## WorkBuddy 接入

先 `project_get` 找到本项目某个 `craftAsset`，沿用其 `prompt` 作为 `goal`、`taskId` 作为 `textureOf`，再使用新 `requestId` 调用 `craft_generate`。需要改变表面描述时可加 200 字以内的 `texturePrompt`，不可同时传 `planJson`。

用户须明确要求云端纹理生成，因为该操作会上传已有 GLB 并产生纹理费用。若任务 `args.textureSource` 存在，不能再使用 `craft_complete_plan` 接续，也不能另建任务绕过等待；用 `task_get` 查询原任务，成功后直接交付 Blender/GLB。
