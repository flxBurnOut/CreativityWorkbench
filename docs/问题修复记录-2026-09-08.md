## 核查后保留的行为与范围

- **二-A、二-B1**：3D 文创、长篇编排、动态后台、云发布仍不实现。craft 用于保存 3D 需求和概念参考，创建工具与工作台范围明确标注不能交付 3D。
- **二-B6**：`https://api.dev.runwayml.com/v1`、`gen4.5`、`2024-11-06` 均见 [Runway 官方 API 示例](https://docs.dev.runwayml.com/guides/using-the-api/)；`dev` 域名不代表误用了测试地址。保留已实现的 Gen-4.5 协议，不开放可能不兼容的任意模型／版本。
- **二-B7**：字幕正文写入 SRT 文件，`subtitles=` 滤镜只使用固定文件名，不插入正文。新增真实 FFmpeg 回归验证 `{}`、反斜杠与逗号能够烧录，不按“滤镜字符串未转义”误改原文。
- **三-3、三-9**：保留有界幂等收据及 writeId 内容保护。同 ID、同内容的传输重试返回既有结果；改变内容属于新操作。这正是避免重复写入的保护。收据最多 1000 条，任务记录仍保留。
- **三-7**：图片／媒体规范化继续保留，以保证解码、方向、输出格式和容量符合工作台约定；目前不提供保留所有 EXIF 或无损转封装模式。
- **二-C 管理范围**：不新增 MCP 项目删除、完整备份／迁移和任务历史删除。网页已有项目管理；本轮清理只处理有成功导入证据的冗余源副本，不删除真实项目或不明测试资料。
- **四 安全边界**：仍是同机可信用户使用的 loopback Runtime，不是多用户认证服务；密钥是 0600 的本机明文文件，不宣称系统钥匙串加密。备份恢复保留原文件 hash／原始字节以保持引用，媒体须通过解码验证；HTML 预览继续使用隔离 CSP。乐观锁支持单 Runtime 内的并发请求，不支持多个独立写入器同时写同一目录。
