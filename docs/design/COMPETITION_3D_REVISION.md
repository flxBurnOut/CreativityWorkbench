## 2. 调整后的定位与双工作台关系

创意工作台的核心定位建议调整为：**把《织梦者》中沉淀的岭南文化知识与视觉依据，转成可探索的 3D 文化空间、可编辑的文创模型，并复用于文旅展示、文化教育和数字文创。**

现有小说、视频、网站、文创流程保留，近期以 3D 空间与 3D 文创为展示主线。网站首先作为 3D 非游戏体验的交付载体；小说与视频生成暂不并行扩建。

| 工作台 | 复用的核心 | 主要交付 |
| --- | --- | --- |
| 生产工作台 | 从初赛提炼的 2D 游戏制作方法 | 其他游戏的可运行 Demo，具体能力以该工作台实际实现为准 |
| 创意工作台 | 从初赛提炼的文化内容、资产语义与表达方法 | 3D 文化空间、3D 文创展示、知识与资产包、非游戏 H5 |

两者可共享文化条目、视觉参考和来源标识，各自能独立使用。创意工作台不以启动生产工作台或游戏引擎为前提。现有 2D 素材可提供参考，但不能把贴图或转台视频直接称为可编辑 3D 模型。

## 3. 最值得展示的三个创新点

这些是拟验证的产品创新点，不宣称技术首创；价值需要通过实际行为和复用结果证明。

### 3.1 文化依据绑定到 3D 对象

文化资料不仅用于生成提示词，还与空间对象、模型部件及讲解热点建立关联。用户点选一扇窗，既能近距离查看造型，也能看到相关资料、哪些属于有依据的文化描述、哪些是当代设计发挥。

例如，广州市林业和园林局的资料介绍了满洲窗的玻璃运用及“画心／衬底”划分。可以据此制作原创的结构示意模型，并把相关知识绑定到部件；未取得测绘数据时，不称为某座历史建筑的精确复原。[文化依据](https://lyylj.gz.gov.cn/kpyd/zhzy/content/post_9665427.html)

演示证据：在空间中选中对象 → 高亮部件 → 展示来源与设计说明 → 导出的独立作品仍保留这份关联。

### 3.2 用自然语言修改可理解的空间对象

用户可以说“把这件展品移到入口旁”“把窗框改成深木色，保留玻璃配色”“改成适合小学生的讲解”。系统将请求转成限定对象上的具体操作，立即展示变化并提供撤销。

模型材质、对象布局和讲解内容分别保存，修改其中一项不会不必要地重做整个场景。对于已有命名部件或参数化构件，允许确定性的局部编辑；对于不可分部件的外部网格，只提供确实支持的整体材质、缩放或替换，不能承诺任意模型都能精确改动某个局部。

演示证据：同一对象修改前后对比；撤销后恢复；文化来源和未修改对象保持；超出能力的请求给出具体说明。

### 3.3 同一份文化资产，形成两种非游戏作品

用户在文化空间中保存的一件模型，可直接用于文创展示页；反向也可把文创模型摆进展览。转用时复用模型、文化来源和设计约束，根据用途生成新的布局、热点及说明。

“用于研学”应改变讲解层次和观察任务，“用于文创展示”应突出模型细节、材质及设计说明。只换标题或配色不计为有效的跨域转化。

演示证据：一个文化包 → 可导览的空间作品 → 独立的文创展示作品；两份产物均可打开，能追溯共同来源，并且编辑副本不会覆盖原作品。

## 4. 新增的 3D 能力

| 能力 | 首版建议范围 | 验收方式 |
| --- | --- | --- |
| 模型预览 | 真实网格、旋转、缩放、复位、标准视角、对象选择 | 从不同方向检查几何，不能只展示一张图片 |
| 模型创建 | 优先可控的参数化文化构件；同时预留真实图生／文生 3D 任务接入 | 明确记录程序构造、用户导入或模型生成的来源；宣称 AI 生成前需跑通真实任务 |
| 模型修改 | 命名部件的材质、颜色、允许范围内的尺寸；导入模型仅开放实际可编辑项 | 变更生效、可撤销，刷新后恢复 |
| 空间组织 | 小型展览空间，自动放置模型、入口视角、导览点和文字热点 | 生成可浏览布局，不要求用户手动搭建全部场景 |
| 空间浏览 | 旋转总览、热点移动、固定导览路线；键盘步行在有时间时增加 | 点击导览能到达各观察点；初版不承担游戏碰撞或角色控制系统 |
| 文化讲解 | 对象级说明与来源卡；按参观人群调整表达 | 说明与被选对象一致，无依据内容标为设计推演 |
| 双向复用 | 模型进入空间；空间内模型派生独立文创展示 | 派生副本保留来源，原项目不被覆盖 |
| 导出 | GLB 模型、场景说明、文化来源与资产清单；可独立运行的非游戏 H5 包 | 在另一浏览器／干净环境打开；模型重新导入检查 |

“可导出模型”不等于可制造、可 3D 打印或可直接进入生产引擎。首版交付为数字设计与交互展示，不承诺结构工程精度、拓扑修复、角色绑定、动作生成或制造验证。

3D 创作页建议：顶部保留五阶段导航；中间为大尺寸 3D 视口；底部保留自然语言修改框；选中对象时按需展开对象说明与少量属性。文化依据从对象卡展开，默认不占据常驻三栏。

主要操作使用“生成／应用修改”“保存到项目”“用于空间”“导出”。模型导出与空间交付在用户视角可区分，不要求了解 GLB、JSON 或运行时概念。技术规格放在导出详情与使用文档。

首页继续以真实项目为中心，新增两类 3D 项目卡标识和明确标记的体验示例。既有 SVG 庭院插画可以保留，但不能作为 3D 功能已实现的证据。

## 6. 建议首个非游戏 Demo

建议题目描述：**“一扇窗里的岭南”：可交互文化微展与当代文创模型。** 这是样例提案，不是新产品品牌。

选择一个明确的文化构件切入，比在数天内制作整座古城更容易保留来源、控制模型质量并完成复用验证。首个模型建议采用满洲窗的原创结构示意；当代文创可探索桌面陈设等展示形式，具体载体待选定。

完整路径：

1. 从《织梦者》中整理已有相关视觉参考，记录原始文件和用途；补充核实文化资料。若初赛未使用该构件，则如实标为决赛新增的同主题延伸。
2. 用户输入“做一个适合研学的岭南窗文化小展”，系统使用文化包生成说明与布局。
3. 创建或载入带来源记录的 3D 构件，生成小型空间与导览点。
4. 用户点击对象看结构与文化说明，用一句话修改窗框材质或移动展品，然后撤销一次。
5. 将同一模型用于独立文创展示，生成与其用途对应的设计说明。
6. 分别导出文化空间 H5 和文创模型／展示页，在独立环境打开。
7. 另一位使用者修改受众、展品或用途，再导出一份自己的作品，证明工作台可以复用。

建议最小规模：一个小型空间、一个重点模型、至少三个有效知识／观察热点、两种实际用途。数量是本项目控制范围的建议，不是比赛规定。文化包首批 3–5 条有依据的条目即可，不为凑数量生成未经核实的文化知识。

## 8. 技术实现建议与能力边界

继续沿用 Web → HTTP → 共享 Runtime → 适配器。新增能力分别承担文化查询、空间规划、模型创建、受控修改与交付；实现并验证后才登记到 manifest。

### 8.1 浏览器 3D 与模型文件

建议 Three.js 承担视口、对象选择与场景展示，glTF／GLB 作为模型交换格式。官方提供加载与导出工具；应用仍需自己实现编辑、文化绑定、任务状态及交付逻辑。[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)、[GLTFExporter](https://threejs.org/docs/pages/GLTFExporter.html)

GLB 保存几何与材质；导览热点、文化依据、用途和编辑约束以独立的场景说明保存。不能假设导出 GLB 后网页的交互逻辑也会自动导出。H5 包应包含实际运行代码、依赖、模型和说明，打包后实测资源路径。

### 8.2 两条互补的模型创建路径

- **参数化路径：** 明确部件和可调参数，由程序构造原创文化示意模型；AI 只输出受校验参数或操作。适合需要稳定部件编辑与文化解释的窗、展架、展示底座等对象。这属于 AI 辅助参数化创作，不能描述成生成模型凭空恢复了真实建筑。
- **生成式路径：** 对复杂装饰或单件文创，评估腾讯混元生 3D 的文本／图片任务接口。官方采用提交任务与查询结果的接口，可返回模型文件。优先作为可替换服务端适配器验证，账号可用性、输出质量、时长与成本均需实际样例确认。[提交任务](https://cloud.tencent.com/document/product/1804/123447)、[查询任务](https://cloud.tencent.com/document/product/1804/123448)

图片生成、图片转 3D 和网格编辑是不同能力，不把图像编辑 API 当成网格编辑服务。对模型形体的大幅返工需要新任务或明确的几何算法，保留旧模型并呈现差异，不承诺局部几何绝对不变。

### 8.3 受控修改与保存

自然语言经模型解释后，产生有限操作，例如修改材质、移动指定对象、调整允许尺寸、替换讲解、加入指定资产。使用稳定对象 ID、类型与范围校验、当前版本检查和撤销记录执行，不直接运行模型生成的任意脚本。

增加独立的文化条目、模型资产、场景对象、导览热点、修改记录、生成任务和交付包记录。模型二进制与纹理保存在受控文件存储中，不随每次文本编辑重复写入整个工作区。旧 IndexedDB 草稿保留读入与迁移方案；先备份再迁移，不能改枚举后使旧项目无法打开。

外部模型生成采用异步任务，保存供应商任务 ID、输入快照和当前状态，刷新只查询已有任务。供应商完成后先下载并校验模型，才能显示可用。腾讯文档列出的结果文件链接有效期为 24 小时，不能直接作为永久交付地址。[文件结构](https://cloud.tencent.com/document/api/1804/120828)

### 8.4 WorkBuddy 交付不能省略

普通网页可运行，不自动证明已经符合 WorkBuddy 工作台装载要求。需要核实比赛当前使用的打包／加载方式，在实际 WorkBuddy 环境装载作品，验证入口、提示词或 Skill、文化包、运行依赖和使用说明能够交接给陌生人。

当前仓库 MCP 仅提供只读 manifest；不能据此宣称已有 3D 工具或 WorkBuddy 集成。首版只对外提供实际需要的能力，不为展示而添加没有调用方的工具。

生成阶段可以依赖配置好的服务端；已导出的非游戏体验建议不依赖生成 API，以便现场稳定观看。这是产品建议，不是套用动画赛道的离线要求。未配置模型服务时可导入已有合法资产并制作作品，界面必须标明导入来源；离线作品不冒充现场 AI 新生成。
