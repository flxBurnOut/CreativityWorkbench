# 生成附近整机卡死：资源保护修复

## 现场证据与判断范围

用户报告在文字生成时整机卡住，并提供了 `signal timed out` 界面截图。随后提供的另一张截图转述 Windows 日志：`ffmpeg.exe` 使用 44,325,015,552 字节虚拟内存，随后出现资源不足和其他应用异常。该截图不是原始事件日志，也未包含进程启动命令。

因此，FFmpeg 资源耗尽是本次重点排查方向；不能仅凭这些材料断言具体是哪条 FFmpeg 命令或哪个任务引发。当前主机近三天 System / Event ID 2004 查询未返回对应事件。没有在故障机器上重现 41 GiB 分配，也没有作出现场故障已消失的声明。

文字模型使用远端 API，本身不启动 FFmpeg。但是项目状态轮询可以恢复已有视频任务的文件接收和转码，与点击文字生成在时间上重叠。原实现没有媒体进程总内存上限，多个入口可并行启动处理，部分补音源没有有限时长。

## 本次变更

- Windows 媒体启动器先加入 Job Object，再创建媒体进程；保护进程和子进程总提交内存最多 1 GiB。没有申请子进程脱离 Job 的权限；关闭保护进程时终止整个 Job。资源保护不能建立时阻止启动，无不受保护的降级执行。
- Windows 同一会话通过命名 Mutex 串行运行本工作台的媒体命令；Node 内也串行执行，最多接纳八条运行中或排队命令。
- 编解码与滤镜限制为两个线程；单次 FFmpeg 分配上限 64 MiB、复用队列 128。单次分配限制不等于总内存限制，总提交内存由 Windows Job 约束。
- 媒体命令最长 180 秒，取消/超时结束保护进程并清理真实子进程。等待执行锁最多 170 秒。
- 合成时静音源和补音明确使用镜头时长。
- 媒体进程失败或无法启动资源保护后，停止该任务的自动恢复，保留收到的文件，避免状态查询反复启动异常处理。
- 图片交接读取和解码移出 HTTP 状态查询等待链，同一任务不会重复并发解码，恢复处理与新增任务共用并发计数。
- 状态轮询与项目同步禁止请求重叠，隐藏页面暂停任务轮询；普通保存仅检查已导入媒体文件的引用，不再把每个媒体文件读入内存。图片预览延迟加载并异步解码；超时显示中文说明，状态恢复后清除轮询错误。

## 验证

- 真实 Windows 保护进程：中文、空格、引号与末尾反斜杠参数传递正确。
- 真实子进程串行运行；失败后释放队列。
- 在 256 MiB Job 限制下先验证正常子进程能运行，再验证请求总计 512 MiB 分配的子进程被拒绝。此测试未尝试大规模耗尽主机资源。
- 取消保护进程后，验证实际子进程 PID 已不存在。
- 并行十二次图片状态查询及时返回，图片只解码一次，取消后的迟到结果仍可找回。
- 媒体启动失败后，重复查询十次也不会重新读取或转码。
- `node --experimental-strip-types --test tests/resource-guards.test.mjs tests/generation.test.mjs`：20/20 通过。
- `tests/outputs.test.mjs`：10/10 通过，包含真实 FFmpeg 解码、导入、混音、字幕、多镜头合成；MCP 实际 stdio 媒体闭环也在完整测试中通过。
- 完整测试最近一次运行：106 项，104 通过，两项失败，分别为 Windows 符号链接权限不足与 POSIX `0600` 权限断言。后续新增了“处理失败后不反复重启”测试并通过定向验证。
- lint、typecheck、build 通过；这些不是故障机器复测或真实供应商生成质量验收。

## 生效与限制

更新后需要重启工作台 Runtime，再刷新网页；已经运行的旧 Runtime 不会自动加载新启动器。不得把原有外部任务未经核对就再次提交。保护只覆盖经本工作台启动器执行的媒体进程；其他软件自行启动的 FFmpeg 不在本保护范围内。

Windows Job 内存硬限制不应用于非 Windows 系统，后者目前只有排队、线程、单次分配和时长限制。低内存或复杂媒体可能更早失败，处理速度可能下降。

实现参考：[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[Job 扩展限制](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)、[FFmpeg 参数说明](https://www.ffmpeg.org/ffmpeg.html)。
