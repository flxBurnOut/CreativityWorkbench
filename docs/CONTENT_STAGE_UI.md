# 内容阶段界面（2026-09-08）

内容阶段统一采用“小节导航 → 编辑当前稿 → 选择修改范围并填写要求 → 比较建议 → 采用 → 独立进入下一阶段”的流程，适用于全部五种作品类型。

- 当前稿可直接输入、粘贴，沿用原有自动保存与历史记录。
- 空方案展示生成完整初稿入口；已有方案默认修改当前小节。选区修改显示实际选中文字，编辑或切换小节后失效；整份方案需显式选择。
- 修改要求紧贴编辑器。空要求就地提示并聚焦输入框；检查遗漏和另作整份候选收进“其他操作”。
- 内容任务只展示当前作品类型的内容结果。历史按钮查看该类型历史；其他阶段任务保留在对应原有入口。
- 候选按小节对照，可见的复选框控制采用范围，采用按钮显示数量；选区候选展示原选区和替换文字。检查结果只给建议。采用不跳阶段。
- 新内容请求将 instruction 固定在任务参数中，下一轮输入不影响已有候选采用。原文或上游依据改变仍严格阻止覆盖；尚未实现按冲突区域自动合并。旧任务保持原校验方式。
- 生成期间主入口禁用；后台任务、失败重试、提示词和输入记录继续保留。窄屏小节导航横向滚动，对照改为上下排列。

实现：`features/creative-flow/content-editor.tsx`、`generation-api.tsx`、`stages.tsx`、`workbench.tsx`、`app/globals.css`；请求快照复用共享 Runtime 的任务协议和生成逻辑，不修改系统或文化规则。

验证：lint、typecheck、build 通过。npm test 75 项中 73 通过；两项既有 Windows 限制为 symlink EPERM 和 POSIX 文件权限模式差异。新增回归覆盖请求要求快照、原文冲突保护、仅采用指定小节且不跳阶段。

浏览器使用独立 `work/content-ui-qa` 数据与模拟服务验证，未调用真实模型，未更改真实项目内容。已验证就地必填提示、小节生成与原稿对照、修改下一轮要求后采用、选区范围选择、整份候选仅采用指定小节。
