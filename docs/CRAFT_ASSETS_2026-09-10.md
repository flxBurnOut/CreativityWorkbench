# 独立三维资产生成：使用、实现与验收

更新：2026-09-10。当前核心协议 **11**、**31 项 MCP 工具**、两项 WorkBuddy Skills **0.8.0**。本轮新增独立的“一句需求 → 三维资产 → 网页查看 → 下载 Blender 文件”流程，沿用 `craft` 项目类型，不要求先走文字、美术或概念图阶段。

本轮已完成受控结构生成、真实 Blender 文件、共享 Runtime 接收、网页预览和下载验证。真实 DeepSeek 解析请求返回密钥无效，因此尚未通过当前凭据下的全自动自然语言验收；没有替换用户凭据。WorkBuddy 原任务交接协议已验证，客户端实际加载仍待用户复测。

## 1. 可以得到什么

| 输出 | 用途 |
| --- | --- |
| `.blend` | 可在 Blender 中打开的真实网格资产，包含材质与已打包的纹理图片 |
| `.glb` | 自包含的网页预览与通用三维交换文件 |
| 小型结果记录 | 原始需求、受限建模方案、任务 ID、文化资料版本、网格统计和简化说明 |

网页可旋转、缩放、查看当前或历史版本并下载文件。新生成成功后自动显示对应结果，不需要 WorkBuddy 再额外调用“采用”。旧成品与历史版本保留。

这是一项独立资产功能；将资产自动嵌入文创文旅网站、为网站生成三维交互展品，属于后续集成阶段。下载 GLB 不表示本轮已经完成网站嵌入、发布或云端托管。

## 2. 当前支持范围

支持 12 类受控结构：碗、盘、盆、花瓶、罐、锅、瓢勺、茶壶，以及简化骑楼、花窗、柱廊、屋顶构件。器具可在适用范围内指定尺寸、壁厚、轮廓、盖、把手和壶嘴；建筑按对应结构支持层数、开间或屋顶形式。材质支持颜色、粗糙度、金属度，以及内置原创花叶或几何装饰。

不同结构的参数不会互相套用。尺寸输入为厘米；结果统计为米。器具和建筑的尺寸主要描述主体，盖、嘴、把手、屋檐等附属部分可能超过主体尺寸，整体尺寸以生成后的统计为准。花窗的深度表示实际挤出厚度，独立平屋顶的高度表示整块厚度。

目前不支持杯这一独立器形、定制圈足、文字雕刻、复杂动物浮雕、人物或任意雕塑、整条街道、实物测绘复原、任意参考图建模、顶点或材质直接编辑。用户的核心需求无法用支持的结构表达时，应说明缺口，不用相似物冒充完成。网页通过重新描述要求生成新版本；需要直接编辑可下载文件后在 Blender 中处理。

产物定位为原创数字设计与展示资产，不承诺施工、烧制、实体制造或三维打印可行性。不得把“保存了 Blender 文件”写成已验证全部拓扑、工艺或文化细节。

## 3. 网页使用

1. 从首页选择“生成 3D 文创资产”，创建或进入三维项目。
2. 在“资产要求”写一次完整需求，点击“开始生成资产”。例如：

   > 生成一只宽口浅腹的深褐色陶碗，保留完整内壁和碗底，表面略有粗糙感，纯色无文字，用于岭南文旅网站中的器物展示。

3. 已配置文字服务时，工作台自动解析需求、运行 Blender、重开核验并保存成品。未配置文字服务时，按页面提示复制一次原任务请求给已连接的 WorkBuddy；它提交造型方案后，工作台继续执行。
4. 页面显示模型后旋转、缩放检查，点击“下载 Blender 文件”。需要下一版时修改需求并点击“生成新版本”；历史版本可在本页查看与下载。

运行中可以编辑下一轮要求或离开页面。输入草稿与本轮固定请求分开，编辑下一轮不会改变已启动的任务。提交响应不确定时用“核对上次提交”沿用原请求编号；不要连续新建任务。取消会停止本次本地建模，旧成品保留，取消任务不会因迟到交接自动复活。

## 4. 配置与 WorkBuddy

需要本机 Blender。常见安装位置会自动探测，也可在本机服务端配置中设置可执行文件的绝对路径，例如：

```dotenv
WORKBENCH_BLENDER_PATH=D:/Tools/Blender/blender.exe
```

路径须对应真实安装；配置后完整重启工作台服务。`workbench_status.providers.craft.available` 只说明找到了可执行文件，实际任务还会验证 Blender 启动、导出和重开。未找到 Blender 时不生成假文件。

网页一句话自动解析复用已配置的 DeepSeek 文字服务。密钥通过现有服务设置或服务端 `DEEPSEEK_API_KEY` 配置，不填在提示词或公开文件里。没有该密钥时，可以使用 WorkBuddy 当前对话理解需求并交回受限方案；这条三维流程不要求 WorkBuddy 图片接口的自动发送令牌，也不依赖外部图生 3D 服务。

安装包继续由 `npm run workbench:setup` 生成，位于 `work/workbuddy-core`。更新后重启旧 Runtime，并在 WorkBuddy 中重新导入两项 Skills 和连接配置；本地生成 ZIP 不等于客户端已经完成装载。

| 操作 | 作用 |
| --- | --- |
| `craft_generate` | 新需求入口：同一请求 ID 幂等，保存本轮指针后创建 `craft-model` 任务；可直接附 `planJson` |
| `task_get` | 查询原任务、阶段、交接说明与真实结果，不重复生成 |
| `craft_complete_plan` | 用原任务 ID 提交受限 JSON 方案，验证后继续同一个任务 |
| `task_cancel` | 取消本地生成或计划交接，不删除旧成果 |
| `project_deliver` | 返回已保存 Blender 与 GLB 文件的真实路径和下载地址 |

收到网页任务 ID 时，必须接续原任务，不能重新 `task_start`、另建项目或用 `media_import` 代替完成。`planJson` 只包含已公布 schema 的数据，Runtime 不执行模型给出的 Python、脚本或任意命令。相同方案可安全重试；已确定方案不能被不同方案覆盖。具体字段与接续步骤见 [WorkBuddy 三维规则](../workbench/skills/creativity-project/references/craft-assets.md)。

## 5. 文化依据与历史同步

主题资料独立于《织梦者》游戏项目。生成按用户目标与已选择的知识匹配相关资料，在任务与成品中保留条目 ID、版本和边界；不为了凑文化元素把广府、潮汕和客家混为一体。普通器具不必强贴非遗标签。

广彩是装饰工艺，不能仅凭金色花纹称为广彩实物复原；骑楼是具有多种立面表达的建筑类型，默认尺寸不是历史测绘数据。内置装饰为原创转译，不复制来源网页照片、纹样或具名作品。

成功结果进入 `craftAsset` 历史；只有本轮任务指针和生成依据仍匹配时才设为当前模型。过期结果保留在历史而不覆盖新要求。切换作品类型再返回、恢复旧版本、完整备份均保留 Blender 和 GLB 文件引用。文件采用内容哈希命名，重复写入相同内容不会建立另一个正式副本。

## 6. 内存与存储预算

| 环节 | 约束 |
| --- | --- |
| Blender 执行 | 同时一个受控建模进程；生成与独立重开核验共用 180 秒执行预算；子进程内存限制 1 GiB，线程数 2 |
| 几何 | 每件最多 40,000 三角形、240 个 Mesh 对象 |
| 正式文件 | `.blend`、`.glb` 各不超过 32 MiB；文件头检查后流式写入，失败临时文件清理 |
| 项目与任务记录 | 保存需求、计划、来源、统计和文件 ID，不保存网格数组或模型 Base64；生成任务快照排除整份 `flow` 历史 |
| 前端 | 单一当前预览视口，按需渲染；切换或离开时取消请求，释放几何、材质、纹理、监听器与 WebGL 资源 |
| 解码防护 | 文件、访问器解码、网格实例预算分别限制为 32 MiB；内嵌 PNG 单张不超过 1024²，总像素和纹理实例各不超过 4M；拒绝 sparse、无 bufferView、越界、循环节点、动画、蒙皮、压缩扩展及外部资源 |

当前 D 盘检出下，进程临时目录是 `work/tmp/process`，建模任务临时目录是默认 `work/data/render/craft-*`。建模进程退出后在 `finally` 中只清理本次拥有的目录；正式文件留在 `work/data/files`，任务及小型历史元数据正常保留。测试夹具使用项目内临时目录并在结束后清理。若另行设置数据目录，建模目录随配置移动。

这些设置不修改 Windows 全局临时目录，也不删除用户旧作品、历史记录或其他软件缓存。子进程 1 GiB 不是整个浏览器、工作台或 WorkBuddy 的总内存上限。大型历史备份仍有现有 JSON 容量和内存边界，详见 [资源审计](RESOURCE_AUDIT_2026-09-10.md)。
