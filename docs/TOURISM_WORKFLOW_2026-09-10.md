## 内存处理

- 任务缓存改为容量与条数双重限制：最多 64 条、约 8 MiB 的字符串权重；源码检查缓存最多 128 个标识。历史仍在磁盘，不因缓存淘汰删除。
- 状态列表逐条读取并移除完整项目快照；新任务快照不再复制所有历史版本。前端历史按批查看，展开某一版本时才渲染正文。
- 视频文件按请求范围从磁盘读取；网页下载交给浏览器流式保存，避免先生成整个视频 Blob。上传代理也不再额外拼接一整份媒体缓冲。
- 网站/设计资料包逐文件、分块写入；预览只解码所请求的 ZIP 成员，不为每张图片解压整站。未选择成员采用丢弃解码器，避免流式 ZIP 库仍暗中缓存它们。
- 图片处理缓存限制为 32 MiB、并行度 2；图片上传限制并发。音视频预览按用户点击加载；轮询在离开项目时取消，备份按钮阻止重复发起，弹窗关闭后移除内容。
- 原有 Windows FFmpeg Job Object、1 GiB 媒体进程限制、串行媒体队列、超时和终止保护继续保留。它们约束 Runtime 启动的处理进程，不约束 WorkBuddy 或其他应用自行启动的进程。

`npm run test:memory` 在独立目录完成 30 轮：96 条历史任务、16 MiB ZIP 重复打包与选定成员读取、16 MiB 文件的 120 次 Range 请求。第 10 轮到第 30 轮，GC 后 JavaScript 堆由 19.13 MiB 到 19.31 MiB（增加约 0.18 MiB）；进程 RSS 采样约 219–224 MiB，缓存权重稳定约 7.34 MiB。

这组测试未出现持续明显的堆增长。采样不是瞬时内存峰值，也不证明所有浏览器、WorkBuddy 和真实供应商长时运行都没有泄漏。完整数据：`work/deliverables/memory-check.json`。后续可通过 workbench_status.resources 查看 Runtime 内存与缓存状态。

## 具体非游戏 Demo

`examples/lingnan-visit` 是“岭南行笺”文化专题网站的具体实现，不是工作台生成器模板。`npm run demo:tourism` 在独立项目目录运行真实核心调用：

保存原创短篇 → 选取骑楼知识 → 切换网站 → 沿用完整正文 → 加入 6 组视觉资产 → 准备并采用网站交接包 → 将具体网站源码导入并采用。

输出在 `work/deliverables`：

- `lingnan-cultural-tourism-demo.zip`：可打开的完整网站，带真实 SVG、事实出处、原文与来源记录。
- `lingnan-visit/index.html`：解压后的入口，支持本地打开。
- `lingnan-website-handoff.zip`：工作台真正生成的需求与素材交接包。
- `workflow-evidence.json`：核心调用、项目/任务标识、版本与成品哈希；独立数据目录不覆盖用户项目。

网站有分类搜索、无结果恢复、插画预览、原创故事、个人探索清单、清单下载与 FAQ。不提供未经接入的票务、预约、支付、导航或实时营业信息。
