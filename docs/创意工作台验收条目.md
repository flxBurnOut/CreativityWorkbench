为了判断“能否主要靠 WorkBuddy 完成”，建议额外跑下面三个连续场景，中途不要打开工作台替它补操作；结束后再用网页核对。

| 网站全流程 | “新建验收网站，介绍同一手艺，包含首页、作品展示和常见问题，使用当前对话完成内容，保存、构建并交付预览与 ZIP。” | 实际网站、可用交互、独立运行的 ZIP |
| 多媒体全流程 | “为项目生成葵扇概念图，按我的要求局部修改并定稿；制作两个镜头的视频，配上旁白与字幕，保存并交付 MP4 和 SRT。” | 真实图片及修改版、真实镜头与配音、合成成品 |

每个连续场景再记录一个操作等级：

- **全程对话完成**：初始化后，创作、文件交接、保存和交付均由 WorkBuddy 完成。
- **需要手工协助**：需要用户复制文件、切到网页采用或补写数据。
- **无法完成**：缺少能力、工具调用失败或无法取得成品。

本轮最终按模块给出结论即可：项目与保存、文字、图像、视频、网站、WorkBuddy 操作分别是否通过。**3D 资产、长篇编排、动态网站后台、云发布，以及未封装的管理操作不计入本轮通过项。**

建议执行顺序是：**启动接入 → 项目保存 → 小说 → 网站 → 图片 → 视频 → 异常恢复 → 连续场景**。反馈时直接使用编号，例如：`D04 失败：修改背景时人物也变了；I05 需手工协助：图片必须手动复制回任务目录。`
