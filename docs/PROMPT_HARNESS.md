# 提示词与文化约束：当前实现

更新：2026-09-08。本轮只优化文化关联、作品类型与提示词执行，不扩展长篇或 3D 生成。

## 共用规则与阶段

`lib/workbench/prompts.mjs` 是 Web、Runtime 与 Skill 创作约定的共同来源。规则区分项目设定、文化事实和待核实内容；文化通过行为、空间、器物、材料与叙事表达，不自动古风化、混合地域或堆砌符号。自由文本 culture 继续兼容，不增加必填表单。

创意保留 title/brief/culture 契约；内容保留整体、小节、选区和遗漏检查；美术保留五字段。各阶段追加小说、视频、网站、3D 前期或未确定类型的要求。内容阶段不发送无关的美术文本；美术阶段明确独立字段优先于旧 fullPrompt。短篇与既有 JSON 校验保持。

后台任务记录实际 `submittedPrompt` 与 `promptVersion`，页面任务卡可展开查看。不增加模型评审、自动检索、自动重生成或多 agent 循环。结构正确与文件可解码不代表文化或审美已验收。

## 概念参考图

组装顺序为用途、文化背景、对象设定、画面、美术、逐张参考用途、修改与输出限制。人物强调辨识，场景强调空间，物件强调形体和材料；小说、视频、网站、3D 前期与封面的用途分别处理。

实际出图同时读取当前材质、配色与保持／排除字段，不只读取 fullPrompt。编辑必须传原图；默认保留原图风格，明确换风格可勾选返工窗口的选项或 MCP 传 newStyle:true。不能用重新设计冒充局部返工。参考用途依旧为文字说明，不声称进行了未实现的自动看图分析。

美术参考不自动成为成品素材；选定概念图提供默认素材，视频明确选择的首帧与网站勾选的素材表示本次实际用途。媒体输入的内容哈希进入相关任务依据，图片上传完成后的哈希回填不覆盖用户较新的编辑。

## 单镜头视频

成品页直接显示一个空镜头输入，不要求先生成分镜。填写要求即可保存该镜头；选择 2–10 秒、16:9/9:16 与可选首帧。最终提示词可查看、编辑、复制，实际提交使用相同文本与显示的参数。

单镜头提示词继承相关文化、主体、美术、动作、运镜与保持要求；不将整篇脚本塞进一个镜头。接入的图片参数是实际首帧，不冒充供应商未提供的任意风格控制。

编辑稿保存在 `video.shots[].prompt`，`promptBasis` 记录其整理依据。文化、美术、相关镜头或参数改变时保留编辑稿，提示重新整理或核对后保留。外部视频接口的 1000 字符上限在提交前检查，不静默截断。

片段来源包含当前文化、美术、最终提示词和实际首帧文件；旁白来源包含原文、声音要求与时长。无关项目标题或其他镜头的变化不令当前单镜头任务过期。旧来源记录不具备这些依据，保留文件供下载核对，重新合成前需重新导入或生成。

原分镜、声音与合成界面放在折叠区域，保持已有工具，不作为单镜头的前置流程。

## 网站：准备任务，不实现业务

网站新入口负责整理提示词、选择素材、复制／导出和交接。网站文案、布局、代码与交互由实际执行模型或外部 agent 完整实现。新任务不要求 SiteSpec，不限制 text/gallery/faq、页数或固定模板，也不自动执行模型代码。

`websiteRequest` 保存：

| 字段 | 含义 |
| --- | --- |
| prompt / basis | 最终编辑稿及其项目依据 |
| assetIds | 明确允许用于网站的图片；默认已选定概念图 |
| bundleFileId | 已准备任务包 ZIP |
| source / taskId | 任务包依据和任务记录 |

`kind:website` 在本机准备任务包，无需 DeepSeek 密钥。包内为 PROMPT.md、materials.json、README.md 和实际素材：`asset-*` 可用于网站，`reference-*` 仅按指定方面参考，未采用候选不自动加入。已有旧网站 ZIP 时会附 existing-website.zip，供执行模型读取原文件。包体资料最多 120 MB。

页面可复制提示词、下载 Markdown、保存任务包或交给 WorkBuddy。Web 明确选择 WorkBuddy 时复用已配置的本地助理消息适配器；缺少授权可手动复制交接请求。MCP 始终使用当前对话，不向自己发消息。状态“任务包已准备”不代表网站已生成或已发布。

外部执行端读取任务及实际图片，在用户指定的交付位置完整实现网站，交付源码、资源、运行说明与真实验证结果。外部服务、账号与运行依赖须如实说明；工作台不负责替它实现这些功能。

旧 `website.spec`、HTML/ZIP 与 `website-build` 保留兼容。新任务不会覆盖旧网站，任务包也不会被当作旧网站源码。项目备份包含网站请求记录与任务包。

## 外部 agent 与接入

新增只读 MCP 工具 `prompt_prepare`，共 16 个核心工具。参数为 projectId、kind（image/cover/video-shot/website）和 args；返回当前项目版本、组装提示词及相关素材。视频与网站返回 basis，允许编辑后分别保存到 promptBasis / websiteRequest.basis。

网站流程：prompt_prepare → project_update 保存编辑稿 → task_start(kind:website) → task_get → task_adopt → project_deliver → 当前 agent 实现网站。交付角色 website-prompt 和 website-request-bundle 与旧 website-preview/website-zip 区分。

`npm run workbench:setup` 从共同规则生成两份 Skill 引用并重新打包，无需手动维护两套文化规则。生成 ZIP 不代表 WorkBuddy 已实际加载。Runtime 核心协议升为 3，旧进程需要重启，MCP 会拒绝复用旧协议。

## 验证范围

针对性测试覆盖编辑稿原样提交、独立美术要求与原图传递、文化及媒体来源变化、无关编辑不造成单镜头冲突、素材资格、网站任务包与旧成果并存、持久化及交付、MCP 不自发消息、并发保存图片哈希不覆盖新编辑。

真实 DeepSeek、WorkBuddy、Runway 和网站执行 agent 的结果质量仍需真实样例验收。既有 Windows 符号链接权限与 POSIX 文件权限断言的测试限制不属于提示词功能的验证证据。本轮执行结果与页面检查记录见 [实施验收记录](HARNESS_VERIFICATION_20260908.md)。
