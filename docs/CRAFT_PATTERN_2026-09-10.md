# 器皿平面图案与本机贴合

协议 13，31 个核心工具，WorkBuddy Skills 0.10.0。

在已有碗、盘、盆、瓶、罐、锅、瓢、茶壶下点击「生成文化图案」。工作台沿用原需求与文化资料，生成一张展开的平面纹样，再由本机 Blender 自动贴到外壁，完成后显示新版本，下载 Blender、GLB 和原始图案 PNG。无需新增纹理 API 或 COS；此流程使用设置中已有的图片生成服务，不会把文字 API 密钥当作图片接口密钥。

图片服务为 WorkBuddy 时，有本地助理授权则发送一次原任务消息；没有授权也可复制页面交接请求，在 WorkBuddy 中完成实际生图。只有收到原任务 PNG、完成本机贴图并验证 Blender/GLB 后，才标记整个任务成功。使用外部 Images API 时按现有兼容接口直接请求图片。各服务自己的使用限制与计费仍适用。

## 当前边界

- 仅支持工作台内置规则生成且拓扑未变的八类器皿。建筑分区、人物雕塑、任意导入模型尚不支持此贴图路径。
- 只修改外壁 UV 与颜色贴图，保留顶点、面连接、内壁、底部、口沿连接面、附件、粗糙度与金属度；执行后和重新打开文件后都核对。
- AI 输出平面装饰图，不输出器物照片、UV 网格或光影。脚本按器皿比例铺排，图案与接缝边缘留釉色缓冲。图案质量和文化辨识度仍需实际观看，不能仅由哈希检验证明。
- 植物、花叶、配色是文化主题启发的当代设计，不冒充文物、传统纹样或具体工艺复原。
- GLB 与 Blender 文件嵌入实际纹理，不依赖旁边的 PNG。原版本保留，失败不覆盖现有模型。

## WorkBuddy 原任务接口

新任务调用 `craft_generate`，指定原资产的 `textureOf`、`textureMode:"image"`，`goal` 沿用原资产 prompt。可选 `texturePrompt` 为 200 字以内的补充要求。在当前对话生图时传 `dispatch:"conversation"`，不向自己额外发消息。

收到 `args.textureMode=image` 的既有任务，按其 `handoffInstructions` 生成 PNG，并调用 `task_complete_handoff({taskId,filename})`，filename 为原项目 inbox 内文件名；已导入同项目媒体库时使用 assetId。也可原子写入原任务 `handoff.output`。不能另建图像任务、用媒体入库替代完成、调用 `craft_complete_plan` 或额外采用。查询到 `succeeded` 且 `result.craftAsset` 含真实文件才交付。

相同请求编号重放不重复生图；已收到的图案先持久化再运行 Blender，重启可接续原图片。相同模型、相同图案要求的明确失败重试会复用已经收到的图片。未知供应商提交不会自动重发；取消后不采用晚到图片。旧 `textureMode=hy` 或省略模式的调用仍保持原 HY/COS 语义，避免旧任务无声切换服务。

## 资源与恢复

等待 WorkBuddy 图片时不复制模型、不启动 Blender。输入 PNG 限制 16 MiB、约 1600 万像素，归一到 1024；单张贴图最大 1024。Blender 同时一个受控进程、两个线程、1 GiB 内存上限，贴合及重开验证合计 180 秒，单个模型文件最大 32 MiB。

本轮中间文件位于项目数据目录的独立 `render/pattern-*` 子目录，进程停止后核对归属再清理；无法确认归属时保留并报告。原生图与规范化图片有内容哈希，图片仅以引用进入任务和项目；成功交接重复文件的清理由现有存储工具按哈希证明执行，不扫描删除历史成品。

项目备份增加可选 `media` 字段，保留当前模型、类型分支和历史版本引用的图案。恢复时检查 PNG 内容哈希和文件完整性，缺图不写入不完整项目。大项目继续使用原有整个数据目录备份方式。
