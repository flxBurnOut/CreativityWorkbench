## 网页使用

1. 新建或打开项目，进入“确定创意”，点击“选择文化资料”。
2. 按关键词/文化语境筛选，阅读事实及展开的出处，勾选与作品相关的条目。
3. 项目自动保存引用；“当前项目的文化语境”继续记录时代、虚构设定和待核实点，不被资料选择覆盖。
4. 按原流程生成、预览并采用。在任务的实际输入中可核对“已选文化资料”。增加/移除资料后，旧生成结果与已整理提示词会按新依据检测过期。
5. 展开“查看本次使用的事实与出处”可下载文化依据 Markdown。网站任务 ZIP 与设计 ZIP 包含 `KNOWLEDGE.md`，WorkBuddy 全部交付也返回 `theme-knowledge` 文件。

文化选择是项目共同依据，切换媒介保留；不会自动改写或重新生成已经采用的作品。视频默认提示词用精简事实，完整出处在任务输入中保存；外部视频 1000 字符上限继续校验，超长需手动精简。用户已编辑的最终视频/网站提示词保持原文，新选择导致过期时须重新整理或明确核对。

## WorkBuddy 对话

使用更新后的两个 Skills（0.5.1）、24 工具、核心协议 7。先重启旧 Runtime，再运行 `npm run workbench:setup` 生成导入包；应用内加载由用户验证。

可以说：“找出广彩的官方文化依据，把相关资料加入这个网站项目，保留我的原创人物设定，再整理网站任务。”

工具流程：`project_get` 获取版本 → `knowledge_search` 返回条目 → `knowledge_apply` 按相关性选择 → `project_get.knowledgeContext` 或 `workflow_get` 读取已选全文 → 当前对话创作并 `project_update`，或运行已有生成器。`knowledge_apply` 支持 add/remove/replace，与其他写操作共用版本检查和幂等回执。不要把仅阅读资料说成已加入项目。

## 维护与验证

已发布版本不可原地改写。新增修订文件并在 `knowledgePacks` 注册，同时保留旧版本，使旧项目和备份能够恢复原有依据。新条目须有对应事实的直接来源、地域/时间边界、权利状态；避免只有搜索结果链接或泛化审美词。

目前测试覆盖来源结构、检索、双端保存契约、类型切换/备份、实际文字请求输入、提示词与任务过期、真实 ZIP 中的文化依据以及真实 stdio MCP 客户端。浏览器检查另外记录在[功能核查](FUNCTIONAL_AUDIT_2026-09-09.md)。这些检查证明资料被使用，不证明模型必然遵守资料；生成后的事实、地域和媒体表现仍需验收。
