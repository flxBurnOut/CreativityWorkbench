# 视频与网站交付

更新：2026-09-08。两类交付已接入五阶段界面的「成品」。3D 文创仍排最后。当前已验证本地接口、实际文件处理和模拟服务，真实 WorkBuddy / Runway / DeepSeek 账户与生成质量须另验。

## 视频操作

1. 在内容阶段整理脚本、镜头、旁白和规格，在概念图阶段保存需要使用的首帧参考。
2. 成品页填写目标时长、画幅和补充要求，生成分镜，检查后采用。当前 16:9 / 9:16，每镜头 2–10 秒整数，1–12 镜头，最长 120 秒。不能完整满足范围时，规划返回不支持原因，不应省略已要求内容。
3. 每个镜头可编辑画面、运镜、时长、首帧、字幕和重生成要求。选择 WorkBuddy 或外部 API，逐个提交，预览并采用。也可以导入实际 MP4。修改或失败只需重做相关镜头；镜头重生成使用文字修改和首帧参考，当前不是基于旧 MP4 的逐帧编辑。
4. 填写了旁白的镜头须提供匹配原文的音频。可请求 WorkBuddy 的实际语音能力生成 WAV，也可导入 WAV、MP3、M4A；当前没有单独的外部 TTS API。没有旁白时留空，选择是否保留镜头原声。可导入配乐，以 15% 音量循环到结尾。
5. 点击「合成完整视频」。Runtime 用 FFmpeg 统一画幅、帧率与编码，按顺序拼接，组合声音、生成 SRT，可将字幕烧入画面。视频时长不足、缺少当前镜头、缺少旁白或配音过长会失败并提示调整。不会自动静音掉必需配音、静帧补齐或悄悄截掉旁白。
6. 预览、采用并下载 MP4 和 SRT。最终视频为 720p、H.264 / AAC、24fps；换竖屏时宽 720、高 1280。修改后保留旧成品，重新合成并采用才替换。文件通过 HTTP Range 播放，支持拖动进度。

WorkBuddy 视频与音频使用同一官方消息入口，但**消息接口不保证 WorkBuddy 账户具有视频或语音生成能力**。缺少自动发送 token 时提供手动复制请求。输出分别固定为 `handoff/<任务 ID>/result.mp4` 和 `result.wav`；输入首帧是实际 PNG；完成写入后再重命名到最终路径。失败写 `error.json`。工作台只接收本次指定文件，检查链接路径、大小和解码能力。不能用生成一张图来代替视频成功。

外部接口当前明确支持 [Runway Gen-4.5 API 协议](https://docs.dev.runwayml.com/guides/using-the-api/)，不是任意厂商通用协议：

```dotenv
VIDEO_PROVIDER=workbuddy
VIDEO_API_BASE_URL=https://api.dev.runwayml.com/v1
VIDEO_API_KEY=
```

无首帧请求 `/text_to_video`，有首帧请求 `/image_to_video`；发送 `X-Runway-Version: 2024-11-06`、`model: gen4.5`、`duration`、分辨率比例、至多 1000 字符的完整提示词。首帧 PNG 上限 3.5 MB，以 data URI 实际传入。超限提示精简，不截断文化要求。服务器配置仅本机可读，不传到前端。

供应商任务 ID 在返回后立即持久化。查询 `/tasks/<id>`，同一任务查询间隔至少五秒；重启可继续 GET，不重新 POST。临时输出下载后转成受控文件。默认允许 Runway 域名及 CloudFront HTTPS 下载；其他实际 CDN 域名须由服务端 `VIDEO_OUTPUT_HOSTS` 逐个填写，下载不附带 API 密钥，不跟随重定向。更换 API 地址后不能把旧任务发到新地址查询。

「取消等待」停止本工作台接收结果与本地运行，不调用 Runway 删除接口；已发送请求可能仍运行或计费，应在供应商处另行取消。送达不明时标记待核实，不自动重发。网页关闭后供应商可继续运行，重新打开工作台后恢复查询和文件回收。

媒体上传上限 128 MB，检查时长与 4K 分辨率上限并实际解码，转为 H.264 MP4 或 48kHz 双声道 PCM WAV。合成在本地消耗 CPU；需要 `ffmpeg-static` 和 `ffprobe-static` 下载的可执行文件。可用 `FFMPEG_PATH` / `FFPROBE_PATH` 指向现有版本；FFmpeg 应包含 libx264、AAC、subtitles / libass。Windows 字幕使用系统 Microsoft YaHei；其他系统需安装中文字体。音频素材来源、发音、声画节奏和文化细节须预览核对。

## 网站操作

1. 内容阶段写目标、页面、文案和交互要求；保存需要使用的素材。
2. 成品页生成网站，先展开新结果预览，检查后采用。可切换桌面和 390px 手机预览宽度。
3. 支持 1–5 个哈希导航页面，文字卡片、图库搜索和分类筛选、FAQ 展开；页面文案、主题、主题色和完整结构可手动修改，点击「更新预览与源码」重新打包，无需再次调用 AI。
4. 底部用自然语言提出修改并生成新版本，旧版在采用前保留。下载 ZIP 包含 `index.html`、素材、`site.json`、样式、脚本及 README。解压后双击 `index.html` 即可离线运行，没有安装依赖或外部 CDN 的要求。HTML 内嵌实际图片与脚本，附带独立 CSS / JS 作为编辑参考；直接修改独立文件时需同步内嵌版本。

模型生成受限 JSON 页面结构，项目代码负责校验和编译；不会执行模型生成的命令、安装模型指定依赖或让生成代码进入 Runtime。文字转义，未知素材 ID 拒绝，图片只取现有实际项目资产。隔离 iframe 仅开放脚本，不开放同源、弹窗、表单提交或顶层导航；HTTP CSP 额外启用 sandbox，禁用连接和外部资源。模型没有视觉理解阶段，不声称已识别参考图片。

交付是文化展示或轻交互静态网站，无登录、支付、数据库、表单收集或云端发布。超出范围的请求须列在生成结果的 `limitations`，在预览和包内说明。此阶段没有发布站点。

## 文件、备份与验证

输出在 `work/data/files/<sha256>.<扩展名>`，引用存于项目 `video` / `website`；输入快照、供应商任务号、提示词及候选保留在任务记录。日常刷新不下载整个数据目录，视频/网页请求只在用户触发时创建。

JSON 备份升级为版本 2，包含已引用的 MP4 / WAV / HTML / ZIP / SRT；旧版备份仍可导入。导入逐个检查内容哈希，不覆盖原项目。媒体总量超过 140 MB 时明确停止 JSON 导出，改用停服务后复制整个 `work/data` 的完整备份；导入文件上限 200 MB。JSON 不包含任务历史、未采用结果与交接目录。已引用图片及网站素材不会因概念图移除而误删。

验证记录见 [MULTIMEDIA_VERIFICATION.md](MULTIMEDIA_VERIFICATION.md)。真实验收还需分别完成：WorkBuddy 一个真实镜头与配音；外部服务一次真实提交、查询、播放；完整作品的文化、声音和视觉检查；DeepSeek 网站文案与修改遵循度。当前静态网站交付及本地媒体合成成功不代表上述模型质量已验收。
